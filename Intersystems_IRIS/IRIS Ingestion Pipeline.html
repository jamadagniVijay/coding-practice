IRIS Ingestion Pipeline

How to Create a File Ingestion Pipeline in InterSystems IRIS

A step-by-step guide to build file and API ingestion pipelines with the IRIS Management Portal

Data Flow

Inbound Directory → File Service → Routing Engine → File Operation → Outbound Directory

1. Before You Start

Make sure that you have these items:

  • An InterSystems IRIS instance that runs and is available
  • Access to the Management Portal with administrator permissions
  • Access to the IRIS server file system (terminal or Docker)
Note: This tutorial uses the USER namespace. Make sure that you select the correct namespace before you start.

2. Create the Production

A production is the container for all interoperability components. You must create a production before you can add services, processes, or operations.

1

Open the Management Portal. Go to Interoperability > Configure > Production.

2

Click New to open the Production Wizard.

3

Set the Package Name to Sample.

4

Set the Production Name to SampleIngestionPipeline.

5

Click OK to create the production. The system opens the Production Configuration page.

3. Add the File Inbound Service

The inbound service monitors a directory for new files. When a new file comes in, the service reads the file and sends it to the next component.

1

On the Production Configuration page, click the + button next to Services.

2

In the Service Class field, select EnsLib.File.PassthroughService.

3

Set the Service Name to FileInboundService. Click OK.

4

Set these values in the Settings panel on the right side:

SettingValueDescription
File Path/tmp/iris/inbound/The directory that the service monitors for new files
File Spec*The file pattern to match (asterisk means all files)
Archive Path/tmp/iris/archive/The directory where processed files are kept after the operation reads them
Work Path/tmp/iris/work/A temporary directory for files that the system processes
Call Interval5How often the service checks for new files, in seconds
Target Config NamesIngestionRouterThe name of the next component that gets the file data
5

Click Apply to save the settings.

Important: You must set both the Archive Path and the Work Path. The passthrough service creates a file-based stream that references the source file on disk. Without an Archive Path, the service deletes the source file before the operation can read the stream content. This causes ERROR #5005: Cannot open file errors and 0-byte output files.

4. Add the File Outbound Operation

The outbound operation writes the file data to an output directory. It is the last component in the pipeline.

1

Click the + button next to Operations.

2

In the Operation Class field, select EnsLib.File.PassthroughOperation.

3

Set the Operation Name to FileOutboundOperation. Click OK.

4

Set these values in the Settings panel:

SettingValueDescription
File Path/tmp/iris/outbound/The directory where the operation writes the output files
File Name%f_%Q%!+(_a)The output file name pattern with a timestamp to prevent duplicates
5

Click Apply to save the settings.

5. Add the Routing Engine

The routing engine is a business process that uses rules to send messages to the correct operation.

1

Click the + button next to Processes.

2

In the Business Process Class field, select EnsLib.MsgRouter.RoutingEngine.

3

Set the Process Name to IngestionRouter. Click OK.

4

In the Settings panel, set the Business Rule Name to Sample.IngestionRouterRoutingRule.

5

Click Apply to save the settings.

6. Create the Routing Rule

The routing rule tells the routing engine where to send each message. In this pipeline, the rule sends all messages to the FileOutboundOperation.

1

With the IngestionRouter selected, click the magnifying glass icon next to the Business Rule Name field. This opens the Rule Editor in a new tab.

2

In the Rule Editor, find the rule labeled [1] rule. Click + send to add a send action.

3

Double-click the send element to open the Edit Send dialog.

4

In the Target field, type FileOutboundOperation. Click OK.

5

Click Save and then Compile to save and compile the rule.

Note: This rule has no condition. It sends all messages to the target. To add conditions, you can add constraint expressions to the rule.

7. Verify the Configuration

Before you start the production, check that all three components are correct.

ComponentTypeClass
FileInboundServiceServiceEnsLib.File.PassthroughService
IngestionRouterProcessEnsLib.MsgRouter.RoutingEngine
FileOutboundOperationOperationEnsLib.File.PassthroughOperation

Make sure that the data flows in this order:

  1. The FileInboundService reads files from /tmp/iris/inbound/ and moves each file to /tmp/iris/work/.
  2. The service sends the file data to the IngestionRouter.
  3. The IngestionRouter uses the routing rule to send the data to the FileOutboundOperation.
  4. The FileOutboundOperation reads the stream and writes the file to /tmp/iris/outbound/.
  5. The service moves the processed file from /tmp/iris/work/ to /tmp/iris/archive/.

8. Set Up the Client

The client for this pipeline is any process that puts files into the inbound directory. You must create the directories before you start the production.

Create the directories

The pipeline needs four directories. Create them before you start the production.

DirectoryPurpose
/tmp/iris/inbound/Where new files arrive for processing
/tmp/iris/work/Temporary location while the service processes a file
/tmp/iris/archive/Keeps processed files until the operation reads them
/tmp/iris/outbound/Where the operation writes the output files

If IRIS runs in Docker, use these commands:

docker exec -u 0 my-iris bash -c '\
  mkdir -p /tmp/iris/inbound /tmp/iris/outbound /tmp/iris/work /tmp/iris/archive && \
  chown -R irisowner:irisowner /tmp/iris && \
  chmod 777 /tmp/iris/inbound /tmp/iris/outbound /tmp/iris/work /tmp/iris/archive'

Replace my-iris with the name of your IRIS container.

If IRIS runs directly on the server, use these commands:

sudo mkdir -p /tmp/iris/inbound /tmp/iris/outbound /tmp/iris/work /tmp/iris/archive
sudo chown -R irisowner:irisowner /tmp/iris
sudo chmod 777 /tmp/iris/inbound /tmp/iris/outbound /tmp/iris/work /tmp/iris/archive
Important: The IRIS process must have read and write access to all four directories. If the directories do not exist when the production starts, the service shows an error and the component indicator turns red.

Client methods

You can use different methods to put files into the inbound directory:

  • Manual copy: Use the cp command or a file manager to copy files into /tmp/iris/inbound/
  • Script: Write a shell script or batch file that copies files on a schedule
  • Application: Write an application that creates files in the inbound directory
  • SFTP/SCP: Send files from a remote system to the inbound directory
  • Docker volume: Mount a host directory to /tmp/iris/inbound/ in the container

See Section 11: Docker Commands Reference for Docker volume examples and other useful commands.

Troubleshoot problems

If you see errors, check these common causes:

ProblemCauseSolution
Red indicator on a componentA directory does not exist or has wrong permissionsCreate all four directories and set correct ownership
ERROR #5005: Cannot open fileThe Archive Path is not set. The service deletes the source file before the operation reads the stream.Set Archive Path to /tmp/iris/archive/ on FileInboundService
Output files are 0 bytesSame root cause as ERROR #5005. The operation creates the file but cannot read the stream content.Set Archive Path. The archive keeps the source file available.
Files not picked upThe File Spec does not match the file namesChange File Spec to * to match all files
"Directory does not exist" errorIRIS cannot access the directoryCheck permissions: chmod 777 and chown irisowner

Why ERROR #5005 happens

The EnsLib.File.PassthroughService wraps each file in a %FileCharacterStream. This stream stores a reference to the file path on disk. It does not copy the file content into memory.

When the service picks up a file, it moves the file to the work directory. After the message is sent, the service deletes the file from the work directory. But the operation receives a stream that still points to the deleted file path. When the operation tries to read the stream, the file is gone.

The Archive Path solves this problem. With an Archive Path set, the service moves the processed file to the archive directory instead of deleting it. The file stays on disk until the operation reads the stream content.

Tip: You can clean the archive directory on a schedule. The files in the archive directory are no longer needed after the operation writes the output. Use a cron job or a scheduled task to delete old archive files.

11. Add a REST API Ingestion Pipeline

This section shows how to add a parallel API-based pipeline that ingests data through HTTP requests and writes records to a database table. The file-based pipeline stays active alongside this new pipeline.

API Pipeline Data Flow

HTTP POST → REST Dispatch → API Ingest Service → Database Writer → Database Table

Create the ObjectScript classes

Open the IRIS terminal and compile these five classes. Each class has a specific role in the API pipeline.

a) DTO class (Data Transfer Object) — carries data between production components (Single Responsibility Principle):

Class Sample.DTO.IngestionRequest Extends Ens.Request
{
  /// Name of the file or document that this request represents.
  Property FileName As %String(MAXLEN = 256);
  /// Stream that holds the raw content body from the HTTP request.
  Property Content As %Stream.GlobalCharacter;
  /// MIME type of the incoming content (e.g. text/plain, application/json).
  Property ContentType As %String(MAXLEN = 128);
  /// Origin label that identifies which pipeline sent this request.
  Property Source As %String(MAXLEN = 128);
}

b) Entity class (Persistent) — stores the ingested records (Single Responsibility Principle):

Class Sample.Entity.IngestedRecord Extends %Persistent
{
  /// Original file name or auto-generated label for this record.
  Property FileName As %String(MAXLEN = 256);
  /// Full text content of the ingested payload.
  Property Content As %String(MAXLEN = "");
  /// MIME type that was supplied with the original HTTP request.
  Property ContentType As %String(MAXLEN = 128);
  /// Label that shows which pipeline created this record (e.g. REST API).
  Property Source As %String(MAXLEN = 128)
    [ InitialExpression = "REST API" ];
  /// Timestamp that records when the system received this data.
  Property ReceivedAt As %TimeStamp
    [ InitialExpression = {$ZDateTime($Horolog, 3)} ];
  Index ReceivedAtIdx On ReceivedAt;
  Index SourceIdx On Source;
}

c) Business Operation — reads the message and writes a record to the table:

Class Sample.Operation.DatabaseWriter Extends Ens.BusinessOperation
{
  /// Use Queue invocation so the production queues requests for this operation.
  Parameter INVOCATION = "Queue";

  /// Reads the IngestionRequest message and creates a new IngestedRecord row.
  Method WriteToDatabase(pRequest As Sample.DTO.IngestionRequest,
      Output pResponse As Ens.Response) As %Status
  {
    Set sc = $$$OK
    Try {
      Set record = ##class(Sample.Entity.IngestedRecord).%New()
      Set record.FileName = pRequest.FileName
      Set record.ContentType = pRequest.ContentType
      Set record.Source = pRequest.Source
      Set record.ReceivedAt = $ZDateTime($Horolog, 3)
      If $IsObject(pRequest.Content) {
        Do pRequest.Content.Rewind()
        Set record.Content = pRequest.Content.Read(32000)
      }
      Set sc = record.%Save()
    } Catch ex {
      Set sc = ex.AsStatus()
    }
    Return sc
  }

  XData MessageMap
  {
  <MapItems>
    <MapItem MessageType="Sample.DTO.IngestionRequest">
      <Method>WriteToDatabase</Method>
    </MapItem>
  </MapItems>
  }
}

d) Business Service — receives input from the REST dispatch and sends it to the operation:

Class Sample.Service.APIIngestService Extends Ens.BusinessService
{
  /// No adapter — this service is called directly from the REST dispatch class.
  Parameter ADAPTER = "";
  /// Comma-separated list of target config names to forward requests to.
  Property TargetConfigNames As %String(MAXLEN = 1000)
    [ InitialExpression = "DatabaseWriter" ];

  /// Receives the IngestionRequest from the REST dispatch and forwards it
  /// synchronously to the DatabaseWriter operation.
  Method OnProcessInput(
      pInput As Sample.DTO.IngestionRequest,
      Output pOutput As Ens.Response) As %Status
  {
    Return ..SendRequestSync(..TargetConfigNames, pInput, .pOutput)
  }
}

e) REST Dispatch class — maps HTTP routes to ObjectScript methods:

Class Sample.REST.IngestionAPI Extends %CSP.REST
{
  /// Default response content type for all endpoints.
  Parameter CONTENTTYPE = "application/json";
  /// Character encoding for responses.
  Parameter CHARSET = "utf-8";
  /// Enable CORS so browser-based clients can call the API.
  Parameter HandleCorsRequest = 1;

  XData UrlMap [ XMLNamespace = "http://www.intersystems.com/urlmap" ]
  {
  <Routes>
    <Route Url="/ingest" Method="POST" Call="HandleIngest"/>
    <Route Url="/ingest/:filename" Method="POST"
           Call="HandleIngestWithName"/>
    <Route Url="/records" Method="GET" Call="HandleListRecords"/>
    <Route Url="/records/:id" Method="GET" Call="HandleGetRecord"/>
    <Route Url="/status" Method="GET" Call="HandleStatus"/>
  </Routes>
  }
}
Note: Use %Stream.GlobalCharacter as the stream class. IRIS Community Edition does not include %Stream.GlobalCharacterStream.

Compile the classes

Save each class as a .cls file and load it into IRIS:

# Copy each class file into the Docker container
docker cp IngestionRequest.cls my-iris:/tmp/
docker cp IngestedRecord.cls my-iris:/tmp/
docker cp DatabaseWriter.cls my-iris:/tmp/
docker cp APIIngestService.cls my-iris:/tmp/
docker cp IngestionAPI.cls my-iris:/tmp/

# Load and compile each class
docker exec -i my-iris iris session IRIS -U USER \
  <<< 'Do $System.OBJ.Load("/tmp/IngestionRequest.cls","ck")'
docker exec -i my-iris iris session IRIS -U USER \
  <<< 'Do $System.OBJ.Load("/tmp/IngestedRecord.cls","ck")'
docker exec -i my-iris iris session IRIS -U USER \
  <<< 'Do $System.OBJ.Load("/tmp/DatabaseWriter.cls","ck")'
docker exec -i my-iris iris session IRIS -U USER \
  <<< 'Do $System.OBJ.Load("/tmp/APIIngestService.cls","ck")'
docker exec -i my-iris iris session IRIS -U USER \
  <<< 'Do $System.OBJ.Load("/tmp/IngestionAPI.cls","ck")'

Query the database table directly

You can also query the Sample_Entity.IngestedRecord table through the IRIS SQL interface or terminal:

# Open the IRIS terminal
docker exec -it my-iris iris session IRIS -U USER

# Run a SQL query
Do $System.SQL.Execute("SELECT * FROM Sample_Entity.IngestedRecord")

Or use the Management Portal: go to System Explorer → SQL and run:

SELECT ID, FileName, ContentType, Source, ReceivedAt
FROM Sample_Entity.IngestedRecord
ORDER BY ReceivedAt DESC

12. Docker Commands Reference

Use these commands to manage and troubleshoot the pipeline when IRIS runs in Docker. Replace my-iris with the name of your container.

Container management

# List running containers
docker ps

# Show container logs
docker logs my-iris

# Open a shell inside the container
docker exec -it my-iris bash

# Open a shell as root (for directory and permission changes)
docker exec -it -u 0 my-iris bash

Directory setup

# Create all four pipeline directories
docker exec -u 0 my-iris bash -c '\
  mkdir -p /tmp/iris/inbound /tmp/iris/outbound /tmp/iris/work /tmp/iris/archive && \
  chown -R irisowner:irisowner /tmp/iris && \
  chmod 777 /tmp/iris/inbound /tmp/iris/outbound /tmp/iris/work /tmp/iris/archive'

# Verify directory permissions
docker exec my-iris bash -c 'ls -la /tmp/iris/'

Send and check test files

# Create a test file in the inbound directory
docker exec my-iris bash -c \
  'echo "Test message content" > /tmp/iris/inbound/test-file.txt'

# Wait a few seconds, then check the outbound directory
docker exec my-iris bash -c 'ls -la /tmp/iris/outbound/'

# Read the content of an output file
docker exec my-iris bash -c 'cat /tmp/iris/outbound/*.txt*'

# Check the archive directory for processed files
docker exec my-iris bash -c 'ls -la /tmp/iris/archive/'

Check all directories at once

docker exec my-iris bash -c '\
  echo "=== INBOUND ===" && ls -la /tmp/iris/inbound/ && \
  echo "=== WORK ===" && ls -la /tmp/iris/work/ && \
  echo "=== ARCHIVE ===" && ls -la /tmp/iris/archive/ && \
  echo "=== OUTBOUND ===" && ls -la /tmp/iris/outbound/'

Clean directories

# Remove all output files
docker exec my-iris bash -c 'rm -f /tmp/iris/outbound/*'

# Remove all archive files
docker exec my-iris bash -c 'rm -f /tmp/iris/archive/*'

# Remove everything and start fresh
docker exec my-iris bash -c '\
  rm -f /tmp/iris/inbound/* /tmp/iris/outbound/* /tmp/iris/work/* /tmp/iris/archive/*'

Docker volume for external file delivery

# Start IRIS with a host directory mounted as the inbound directory
docker run -d --name my-iris \
  -v /path/on/host:/tmp/iris/inbound \
  -p 52773:52773 \
  intersystems/iris-community:latest-cd

# Now copy files on the host into /path/on/host/
# They appear automatically inside the container at /tmp/iris/inbound/
